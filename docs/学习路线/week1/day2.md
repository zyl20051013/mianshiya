# 数据模型与CRUD

## 自测题

### 面试官提问 1：Entity / DTO / VO 各解决什么问题？能合并成一个吗？

a:Entity（实例）：与数据表一一对应，负责和数据库交互。如果合并会暴露机密字段给前端

DTO（数据传输对象）：用来接收前端传来的数值，例如注册接口，前端会多传一个“确认密码”，这个只是用来后端校验不需要存库

VO（视图对象）：用来返回给前端，通常会把entity里面的状态数字转换成文字，或者把敏感字段给剔除


### 面试官提问 2：`BeanUtils.copyProperties` 什么时候会“静默不拷贝”？

a：当源对象和目标对象的字段名不一样的时候，或者字段类型不一样（e.g：String和Date），它不会报错，而是直接跳过拷贝

这就是java里面常见的反射黑盒现象，运前不会告诉你出错了，等运行到一定时发现拿不到数据


### 面试官提问 3：为什么中间表（如 `question_bank_question`）用硬删除（真删），不用 `isDelete`？

a：这种只是关系性表有唯一索引，如果删的不彻底的话，下次再添加，会导致索引冲突

+：为啥其他的数据要添加逻辑删除（isDelete），因前端删掉以后，可以暂时存到后端等，用户需要找回的时候方便拿出来，


### 面试官提问 4：排序字段为什么要做白名单校验？

a：防止SQL注入，前端传过来的排序字段会直接拼到SQL的ORDER BY后面，如果有人有歪心思就会导致被乱删数据，所以必须用if写死可以排序字段


### 面试官提问 5：Java 里的 `long` 类型返回给前端，为什么变成了字符串？

a：因为前端javascript中数字精度范围是2^53-1(16位)，但是后端雪花算法生成的id有19位，所以后端会强行把long强制序列化为String发送给前端
