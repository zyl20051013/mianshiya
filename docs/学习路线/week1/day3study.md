### 核心区别：为什么不能“让前端自己跑”？

假设我们不让前端去向后端要 User 了，让前端登录成功后，把 User 存在浏览器的 `localStorage` 里，以后一直用前端的。会出什么问题？

#### 1. 致命问题：刷新页面（F5），前端就“失忆”了

你存在前端 JS 内存里的 User 对象，只要你按一下 F5，或者关掉网页重新打开，**它瞬间就灰飞烟灭了**。
这时候，前端页面一片空白，右上角连个名字都没了。它必须赶紧拿着浏览器底层还留着的 Cookie（手环），去后端调 `get/login` 问问：“我还登录着吗？我到底叫啥名字？” 拿到数据后，前端才能把页面重新画出来。

#### 2. 安全问题：前端的数据是“裸奔”的

如果你让前端自己跑，前端觉得“我是普通用户”。结果黑客按了 F12，把前端 `localStorage` 里的 `userRole = "user"` 改成了 `"admin"`。
黑客点一下“删除题库”，前端一看：“哇，老大来了，发请求！”
如果**后端真的信了前端传过来的这个 User 对象**，那就完了。
所以，**后端绝不认前端传来的 User 数据，后端只认 Cookie 里的 `JSESSIONID`，然后自己去服务器小黑板（Session）里查。**
