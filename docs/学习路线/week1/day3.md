# 登录与权限

## 自测题

### 1. `request.getSession()` 拿到的 Session 属于谁？服务器怎么认出来的？

a：拿到的session属于~~后端~~属于前端发起请求的浏览器会话，

能认出来的原因是登录成功以后后端创建一个Session，并给你发送一个JSESSIONID的唯一标识（存在Cookie），你下次发请求的时候会附带这个Cookie，后端Tomcat拿到以后，就去Session内存池里面查，就知道用户是谁了

+：那么是不是前端修改Cookie就可以拿到别人的数据，有哪些防范措施：

企业防范方法：

1.设置httponly（防XSS），前端无法读取Cookie

2.全栈用Https（防抓包），所有请求都走加密，在公网抓包，拿到的也是加密数据

3.定期更换手环（Session过期）

4.登录成功后重置SessionID

### 2. 服务器重启后登录态还在吗？部署两台服务器呢？

a：不在了，所有的session都在内存上面，重启以后内存被清除，所有账号需要重新登录

如果是部署了两台服务器（集群），没有特殊处理，用户在a服务器登录，请求被发到b服务器，b服务在内存找不到对应的session就会判断你没有登录

解决这个问题就得用到redis，把session从本地内存抽离出来，统一到redis上面，这就是分布式Session

### 3. 密码加盐解决了什么？MD5 加盐今天还够用吗？

a：主要解决“彩虹表”破解问题，即使两个用户的密码一样，由于盐值不同，加密出来的文件也完全不同

+：“现代企业通常会使用 **BCrypt** 或 **Argon2** 这种‘慢哈希’算法。它们故意设计得很慢（算一次需要 0.1 秒），让黑客的暴力破解成本高到无法承受。而且，最好给**每个用户分配独立的随机盐值**，而不是全局共用一个盐值。”

### 4. `@AuthCheck(mustRole = "admin")` 从注解到拦截，中间发生了什么？

a:这里就用了面向切面编程（Spring AOP）

1.拦截器AuthInterceptor，加上@Around("@annotation(authcheck)")切面，意思是所有贴了@Authcheck的都要执行程序先进入拦截器

2.拦截器从注解里读取要求得角色

3.调用userServer.getLoginUser(request)从请求session里获得想要的角色

4对比角色

优点：横切关注点分离，不用大量写if-else，方便后期修改

### 5. `Long` 为什么序列化成 `String` 传给前端？

a:前端用的双精度浮点数，大概是2^53-1（16位）而后端生成得id是雪花算法有（19位），转换成string就可以不会丢失数，以便数据之间的准确性

+：“这是大厂处理超长 ID 的标配方案，在 Java 后端用 `@JsonSerialize(using = ToStringSerializer.class)` 配合全局配置即可完美解决。”
