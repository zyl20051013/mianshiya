# 前端工程化与Next

## 自测题

### 面试官提问 1：`"use client"` 加在 `layout.tsx` 上，意味着什么？

a：相当于它现在是客户端组件，它被打包发到浏览器，能用useState，useEffect以及处理点击事件，但是它失去了服务端组件直接查数据的功能，也影响了SEO

### 面试官提问 2：SSR 时 axios 发出的请求，会带上浏览器的 cookie 吗？哪些页面不能用服务端渲染？

a：不会

SSR是服务器渲染在Node.js服务器上面执行，浏览器还没来得及参与，所以请求根本不会带有JSESSIONID等Cookie

因此但凡需要强制登录账号的页面都不能用纯服务端渲染，它们必须做成客户端，它必须带着Cookie去请求，或者通过Next.js的Cookie（）API从服务端手动获取Cookie拼塞进请求头中

### 面试官提问 3：为什么 antd 要包一层 `<AntdRegistry>`？

a:因为 Ant Design 5 使用的是 **CSS-in-JS** 方案，它的样式是在组件运行时动态生成的。
在 SSR（服务端渲染）时，如果直接渲染出 HTML 字符串发给浏览器，浏览器会先显示没有样式的裸奔页面，等 JS 加载完执行后，样式才突然生效，这会造成**页面闪烁（FOUC）**。
`<AntdRegistry>` 的作用是：在服务器渲染期间，收集所有 antd 生成的 CSS 样式，并直接内联到返回的 HTML 中。这样浏览器一拿到 HTML 就带着完整样式，首屏渲染体验极佳。

### 面试官提问 4：Redux 在这个项目里只存了什么？为什么不把题目列表也放进去？

a：这个项目里 Redux 只存了**当前登录用户的信息（`loginUser`）**。
不把题目列表放进去，是因为题目列表属于**页面级数据**。Redux 适合存储全局共享、且跨页面不经常变化的持久数据。如果把题目列表放进去，会造成 Redux 内存膨胀，且每次搜索、翻页都要去维护 Redux 的状态同步，增加了代码的复杂度。题目列表每次进入页面重新请求，用完即销毁，才是最优解。

### 面试官提问 5：后端改了接口，前端要做哪两件事？

a：

1. 保持后端运行，在前端目录执行 **`npm run openapi`**，重新生成 `src/api` 下的类型和请求函数。
