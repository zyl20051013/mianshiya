## 步骤 1｜读四个核心页面（50 分钟）

| 文件 | 看什么 |
|---|---|
| `src/app/page.tsx` | 主页：两次 `await` 拿题库和题目；`export const dynamic = 'force-dynamic'` 是干什么的 |
| `src/app/questions/page.tsx` | 搜索页：客户端组件 + 分页 + 关键词 |
| `src/app/bank/[questionBankId]/page.tsx` | 动态路由：`params` 怎么拿到 id |
| `src/app/question/[questionId]/page.tsx` | 详情页：最简的一条 SSR 链路 |

读完回答：**这四个页面里，哪几个是服务端组件？为什么？**

## 步骤 2｜亲眼看一次 SSR（15 分钟）

1. 打开 `/questions` 页面 → 右键"查看网页源代码" → 搜索题目关键词
2. 能搜到 = 数据是服务端渲染进 HTML 的
3. 再打开 `/admin/bank` → 源代码里没有数据 = 客户端渲染

这一步看起来简单，但它是你**理解"服务端渲染"最直观的证据**。很多人做了半年项目，也没看过一次源代码。

---

## 步骤 3｜动手：上一题 / 下一题（60 分钟）

题库详情页里，`questionBankVO.questionPage.records` 是有序的题目列表。

思路（自己写，别直接抄）：

1. 找出当前 `questionId` 在 `records` 里的下标
2. 取 `index - 1` 和 `index + 1`
3. 用 `Link` 跳到 `/bank/{bankId}/question/{id}`
4. 边界：第一条没有上一题、最后一条没有下一题（**置灰**而不是隐藏）

写的时候会遇到两个坑，提前告诉你：

- `questionId` 从 `params` 拿到的是**字符串**，和 records 里的 id 比较要注意类型（记得后端把 Long 转成 String 了，这里反而刚好）
- 越界时 `records[-1]` 是 `undefined`，要判空

## 步骤 4｜白板复盘（40 分钟）

把这一条链路完整画出来，每一跳都标上"发生了什么"：

```
浏览器
  → Next 服务端(3000)
  → axios(baseURL 8101)
  → /api/questionBank/get/vo
  → DispatcherServlet
  → QuestionBankController
  → QuestionBankServiceImpl.getQuestionBankVO
  → QuestionMapper (MyBatis-Plus)
  → MySQL
  → Entity → VO
  → JSON
  → React 渲染
  → HTML 返回浏览器
```

画完合上纸，**口述一遍**。卡在哪一跳，就回看那一天。

## 步骤 5｜写 5 分钟口述稿（30 分钟）

按这 5 段写，每段 3~5 句：

1. **项目是干什么的**，有哪几类用户，核心流程是什么
2. **4 张表怎么设计的**，为什么这么设计（重点讲中间表和逻辑删除）
3. **一条请求的完整链路**（用"题库详情页"举例）
4. **你做的改造**：标签筛选——改了哪三个文件，怎么验证的，遇到什么问题
5. **你现在还不会什么**（诚实且具体，比如"ES 的倒排索引我只知道概念"）

第 5 段最重要。面试官最爱问"你觉得哪里还能优化"，有准备的人和不准备的人，差距就在这。

## 步骤 6｜整理笔记 + 攒简历素材（40 分钟）

1. 把 7 天的笔记合并进 `00-项目地图.md`（ER 图 + 分层图 + 链路图）
2. `problems.md` 里挑 3 条最典型的坑，写清"现象 / 根因 / 解决"
3. 写 3 条简历素材，格式：**做了什么 + 用了什么 + 结果是什么**

示例（照这个结构写你自己的）：

- 独立完成题库模块的增删改查与分页查询，基于 MyBatis-Plus 动态条件封装统一查询入口，支持标题/标签/创建人等多维筛选
- 排查并修复题目列表的用户信息展示问题，将循环内单条查询改为批量查询 + 内存组装，10 条数据的查询次数从 11 次降到 2 次
- 基于 Next.js App Router 实现题库列表与详情的服务端渲染，页面源码直出题目内容，提升首屏速度与 SEO 表现

> 现在这些还撑不起一段完整的项目经历，但它们是原材料。第三阶段结束后再组装。

## 下周预告：第二阶段

你会发现第一周埋的伏笔全部炸出来：

| 第一周的问题 | 第二阶段的答案 |
|---|---|
| 登录态存在 Session，多台服务器怎么办 | Redis 分布式 Session |
| 刷题记录怎么存才省空间 | Redis BitMap |
| `like '%x%'` 用不上索引 | Elasticsearch 倒排索引 |
| 批量绑定题目很慢 | 批处理优化 + 线程池 |
| 热门题库每次都查库 | Caffeine + HotKey 多级缓存 |

带着这些问题进第二阶段，你学的就不是"技术名词"，是"解法"。
