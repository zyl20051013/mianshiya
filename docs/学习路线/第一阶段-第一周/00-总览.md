## 一、这份手册要解决什么

你现在的状态是"知道一些，但不成体系"。这一周**不要试图补齐所有知识**，而是用项目把知识"挂"起来：

- 跑通一条完整链路（浏览器 → Next SSR → Spring → MySQL）
- 能画图、能口述、能改代码
- 知道自己缺什么（这是"查漏补缺"的真正含义）

一周结束后，你应该能合上电脑讲 5 分钟："这个平台是怎么运转的。"

## 六、笔记怎么记

```
docs/
├─ 00-项目地图.md      # 业务主线、ER 图、分层图（每周更新）
├─ 01-环境与启动.md    # 能复制粘贴的启动步骤
├─ week1/day1.md ... day7.md
├─ problems.md        # 现象 / 根因 / 解决 / 下次怎么避免
└─ questions.md       # 没搞懂的，每周清一次
```

每天的 `dayX.md` 只回答 6 个问题，多了不写：

1. 今天这条链路，数据从哪来到哪去？
2. 哪个文件是关键？为什么放在这一层？
3. 作者为什么这么设计？换我会怎么做？
4. 我踩了什么坑，根因是什么？
5. **今天学到一个能迁移到别的项目的套路是什么？**
6. 还有哪 3 个问题没搞懂？

第 5 条最重要——面试考的从来不是"你做过什么"，是"经验能不能迁移"。

## 七、卡住时的排查顺序

按这个顺序走，90% 的问题 5 分钟内能定位：

1. **看终端**：后端日志有没有异常栈？前端有没有报错？
2. **看 F12 → Network**：请求发出去了吗？状态码多少？响应体是什么？
3. **看 SQL**：配置里开了 `log-impl: StdOutImpl`，控制台会打印每条 SQL，直接看它查了什么。
4. **二分法**：注释掉一半代码，看问题还在不在。

还不行，再记进 `problems.md`，写清"现象 + 你试过什么"，别只写"报错了"。
