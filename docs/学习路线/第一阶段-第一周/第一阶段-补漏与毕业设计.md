# 第一阶段收口：模糊诊断 + 三天毕业设计

> 适用：已经按第一周手册走完 7 天，但感觉"好像懂了，又说不清"。
> 目标：把"读过"变成"能写"，用 3 天给自己一个明确的及格线。

---

## 一、先回答你的问题：第一阶段算结束了吗

要分两个口径：

| 口径 | 结论 | 说明 |
|---|---|---|
| **教程口径** | 结束了 | 13 条大纲走完，代码跑通，页面能点 |
| **能力口径** | 大概 60% | 你能"看懂 + 小改"，但还不能"独立从零写一个模块" |

**模模糊糊不是你笨，是第一周的设计结果。**

第一周我故意安排成"70% 读 + 30% 写"——因为你需要先建立全局感，否则一上来就写会瞎写。但读出来的理解是**别人的**，只有自己写一遍，才会变成你的。

所以现在的正确动作不是"再读一遍"，而是**闭卷造一个新模块**。

---

## 二、模糊的四种类型（对号入座）

模糊感不是笼统的，它一定落在某一层。先判断你属于哪种：

| 类型 | 症状 | 根因 |
|---|---|---|
| **① 分层模糊** | 说不清一个请求在哪一层被处理，Controller 和 Service 各干什么 | 没自己写过一条链路 |
| **② 数据模糊** | 说不清 DTO / VO / Entity 什么时候转换、为什么要有三个 | 只看了定义，没做转换 |
| **③ 状态模糊** | 说不清登录态怎么来的、权限从哪判断 | 没亲手调过登录 + 权限接口 |
| **④ 边界模糊** | 说不清哪些是框架自动做的（分页、逻辑删除、参数绑定） | 没试过"删掉某行代码看会怎样" |

大多数人同时中了 ①②，少数人卡在 ③。

## 三、11 道自测题（10 分钟，别查代码）

按层分组，答不出的记下题号。

### A. 分层（4 题）

1. 一个 `POST /api/questionBank/add` 请求，从进 JVM 到返回 JSON，依次经过哪些类或组件？至少说 6 个。
2. 参数校验为什么 Controller 判一次空、Service 里 `validXxx` 又校验一次？只留一处行不行？
3. `@Resource private QuestionBankService questionBankService;` 注入的是接口，实际运行的是哪个类？为什么这么写？
4. `QuestionBankMapper` 是个接口，没有实现类，为什么能 `selectById`？

### B. 数据（3 题）

5. `QuestionBankAddRequest`、`QuestionBank`、`QuestionBankVO` 分别出现在哪一层？为什么不合并成一个类？
6. 题目的 `tags` 在数据库里是什么类型？在 `QuestionAddRequest` 里是什么类型？谁负责转换？
7. 逻辑删除一条题目后，`questionService.list()` 还能查到它吗？为什么？

### C. 状态与权限（2 题）

8. 用户登录后，后端凭什么在"下一个请求"里认出他？前端做了哪些配合？
9. `@AuthCheck(mustRole = "admin")` 和 `userService.isAdmin(user)` 有什么区别？各自用在哪？

### D. 前端（2 题）

10. `app/banks/page.tsx` 里那句 `await listQuestionBankVoByPageUsingPost(...)`，是在浏览器执行还是 Node 执行？你怎么证明？
11. 后端改了一个接口的字段，前端要做什么？不做会出什么问题？

### 评分

| 答对 | 判断 | 接下来 |
|---|---|---|
| ≤ 5 题 | 正常，第一周就是这个水平 | 老老实实做下面的三天 |
| 6~9 题 | 有基础，但没串起来 | 三天里重点做 Day A + Day C |
| ≥ 10 题 | 其实不模糊，是没自信 | 可以直接进第二阶段，三天当加餐 |

## 四、三天毕业设计：造一个"题单"模块

**不许看官方对应代码**（项目里没有这个模块，正好）。可以查 MyBatis-Plus / Next.js 官方文档。

### 需求

用户可以创建"题单"（比如"Java 高频 20 题"），管理员可以管理所有题单。

> 为什么选"题单"而不是复刻题库？因为结构和题库几乎一样（你能迁移），但项目里没有现成代码（你不能抄）。**这才是检验。**

### Day A｜后端（4 小时）

**A1. 建表（30 min，SQL 给你，重点是看懂）**

```sql
create table if not exists question_set
(
    id          bigint auto_increment comment 'id' primary key,
    title       varchar(256)                       not null comment '标题',
    description text                               null comment '描述',
    userId      bigint                             not null comment '创建用户 id',
    editTime    datetime default CURRENT_TIMESTAMP not null comment '编辑时间',
    createTime  datetime default CURRENT_TIMESTAMP not null comment '创建时间',
    updateTime  datetime default CURRENT_TIMESTAMP not null on update CURRENT_TIMESTAMP comment '更新时间',
    isDelete    tinyint  default 0                 not null comment '是否删除',
    index idx_title (title),
    index idx_userId (userId)
) comment '题单' collate = utf8mb4_unicode_ci;
```

建完问自己：为什么 `userId` 不能为空？为什么 `isDelete` 有默认值？

**A2. 写 7 个类（2 小时，今天的主菜）**

按这个顺序写，每写完一个就编译一次：

```
model/entity/QuestionSet.java
model/dto/questionset/QuestionSetAddRequest.java
model/dto/questionset/QuestionSetUpdateRequest.java
model/dto/questionset/QuestionSetQueryRequest.java   （继承 PageRequest）
model/vo/QuestionSetVO.java
mapper/QuestionSetMapper.java                        （extends BaseMapper<QuestionSet>）
service/QuestionSetService.java                      （extends IService<QuestionSet>）
service/impl/QuestionSetServiceImpl.java             （extends ServiceImpl<...>）
controller/QuestionSetController.java
```

**接口清单（9 个）**：

| 方法 | 路径 | 权限 |
|---|---|---|
| POST | `/questionSet/add` | 管理员 |
| POST | `/questionSet/delete` | 管理员 |
| POST | `/questionSet/update` | 管理员 |
| POST | `/questionSet/edit` | 本人或管理员 |
| GET | `/questionSet/get/vo` | 公开 |
| POST | `/questionSet/list/page` | 管理员 |
| POST | `/questionSet/list/page/vo` | 公开 |
| POST | `/questionSet/my/list/page/vo` | 登录 |
| GET | `/questionSet/count` | 公开 |

**必须踩到的 4 个坑（踩到才算学到）**：

1. `QuestionSetQueryRequest` 继承 `PageRequest` 后，`getCurrent()` 默认值是多少？没继承会怎样？
2. `getQueryWrapper` 里拼条件，`title` 用 `like`，`userId` 用 `eq` —— 为什么不一样？
3. `add` 时 `userId` 从哪来？为什么不能让前端传？
4. `delete` 时"本人或管理员"怎么判断？只判断 `isAdmin` 会漏什么？

**A3. 验证（1 小时）**

用 doc.html 依次调：登录 → add → get/vo → 改库把角色改回 user → 再 add（应该 40101）。

### Day B｜前端（4 小时）

**B1. 生成接口（15 min）**

后端跑着，`npm run openapi`，确认 `src/api/questionSetController.ts` 和 `typings.d.ts` 里出现了新类型。

**B2. 列表页（90 min）**

新建 `src/app/questionSet/page.tsx`。

**先做决策，再写代码**：这个页面用服务端组件（`async` + `await`）还是客户端组件（`"use client"` + `useEffect`）？

判断依据：数据是公开的、要 SEO → 服务端；要交互、要登录态 → 客户端。写之前先在纸上写出你的选择和理由。

**B3. 管理页（90 min）**

新建 `src/app/admin/questionSet/page.tsx`，用 `ProTable`：

- `columns` 里至少有：id、标题、描述、创建时间、操作
- `request` 返回 `{ success, data, total }`
- 新建/编辑用两个受控 Modal

**B4. 菜单与权限（45 min）**

`config/menu.tsx` 里加两项：`/questionSet`（公开）、`/admin/questionSet`（`access: ACCESS_ENUM.ADMIN`）。

用普通用户登录，确认管理菜单**看不见**；但接口仍然能调通吗？（这就是"前端权限不算安全"的实证）

### Day C｜联调 + 口述（4 小时）

**C1. 走完整流程（60 min）**

管理员建题单 → 前台看到 → 普通用户尝试调 add（失败）→ 改库提权 → 再试（成功）。

**C2. 画图（60 min）**

画三张：

1. `question_set` 的 ER 图（和 user 的关系）
2. 你的后端分层图（Controller → Service → Mapper → MySQL）
3. 一次 `GET /questionSet/get/vo` 的完整时序（含前端在哪执行）

**C3. 对照官方（60 min）**

打开 `QuestionBankController` / `QuestionBankServiceImpl`，只找差异，列 5 条：

- 我少写了什么？
- 我多写了什么？
- 作者哪个处理比我的好？
- 哪个地方作者写得比我想的简单？
- 如果线上出问题，哪一版更好排查？

**C4. 讲一遍（60 min）**

对着空气讲 10 分钟：

1. 我造了一个什么模块
2. 表怎么设计的，为什么
3. 一次请求经过哪些层
4. 权限怎么做的
5. 前端为什么这么选（SSR / CSR）
6. 遇到最大的坑是什么，怎么定位的

讲不顺的地方，就是你要回去补的地方。

## 五、及格线：什么时候可以进第二阶段

四条全过才算：

- [ ] 不看代码，能写出 Controller + Service + Impl + Mapper 四层
- [ ] 能解释每个类为什么存在（Request / Entity / VO / Query）
- [ ] 能讲清一次请求的完整路径，包括前端在哪个进程执行
- [ ] 遇到 404 / 401 / 500，能自己定位到层（而不是问我）

**四条都过** → 第一阶段真的结束了，进第二阶段。

**过 2~3 条** → 再做一遍，换个模块（比如"标签 tag"），第二次会快很多。

**过 0~1 条** → 别急着做新模块，回到第一周 Day 2/Day 3，把 add 链路手抄一遍再默写。

## 六、一句实话

"感觉自己模模糊糊"是好事——说明你开始意识到"看懂"和"会写"的差距了。

很多人做完项目还觉得自己很行，那才是真的危险。

**这一周你不需要学新东西，只需要把已经看过的，亲手写出来一次。**
