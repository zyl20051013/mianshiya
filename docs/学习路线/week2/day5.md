# ES入门与建索引

## 自测题

### 面试官提问 1：倒排索引和 B+ 树索引的本质区别是什么？

a:B+树索引是正排，它是基于主键“id”去建立树形结构，查询是根据id或者前缀去定位数据。如果遇到LIKE ‘%JVM%’，这种没有前缀的模糊匹配，B+树就失效了，只能搜索全表，对数据库压力很大

倒排索引是反向的，他是把文本分词以后，以key形式存储，包含该词的文档id列表”为 Value 建立映射，查询时直接通过词典定位到文档，速度极快（O(1)级别），并且能根据词频计算相关度打分。

### 面试官提问 2：`text` 和 `keyword` 分别什么时候用？

a：**`text`**：用于**全文检索**。它会被分词器切分，主要用于 `match` 查询。比如文章标题、正文内容。

**`keyword`**：用于**精确匹配、过滤和聚合**。它不会被分词，整串存储。比如标签（`tags`）、状态码（`isDelete`）、用户 ID。

### 面试官提问 3：为什么建索引用 `ik_max_word`、搜索用 `ik_smart`？

a:这就是为了平衡“召回率（查得全）”和”准确率（查的准）“，

* 写入数据建立索引时，用 `ik_max_word` 进行最细粒度切分，把所有可能的词都存进倒排表，保证用户搜任何相关词都能命中（提高召回率）。
* 用户搜索时，用 `ik_smart` 进行粗粒度切分，只提取最核心的词去匹配，避免把搜索词切得太碎导致搜出一堆无关的噪音数据（提高准确率）。

### 面试官提问 4：`filter` 为什么比 `must` 快？

* `must` 必须匹配，且**会参与相关度打分（计算 `_score`）**。计算分数需要耗费 CPU 性能。
* `filter` 必须匹配，但**绝不参与打分**。因为不需要算分，ES 底层会对 `filter` 的查询结果进行**缓存（Filter Cache）**。
* 所以对于 `isDelete = 0`、`userId = 1` 这种不需要排名的条件，全丢进 `filter`，速度极快。


### 面试官提问 5：为什么刚写入的数据搜不到？

因为 ES 是“近实时（NRT，Near Real-Time）”的。
为了性能，ES 写入数据后不会立刻落盘建立倒排索引，而是先写进内存缓冲区。默认每隔 **1 秒**（`refresh_interval`），才会执行一次 `refresh`，把缓冲区的数据生成新的 Segment（段）供搜索使用。
如果业务要求立刻可见，可以在写入 URL 后加 `?refresh=true`，但这会严重影响写入性能，生产环境绝不建议这么做。
