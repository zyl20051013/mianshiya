# 自己遇到的问题

## 倒排索引

### 面试官怎么考这道题？

**问：MySQL 有索引，为什么还要用 Elasticsearch 做全文搜索？**
**满分回答**：

> “因为 MySQL 的 B+ 树索引是基于‘最左前缀原则’的正排索引，遇到 `LIKE '%xxx%'` 这种模糊匹配就会失效，变成全表扫描。
> 而 ES 采用的是**倒排索引**，它将文本分词后，以‘词’为 Key，‘文档 ID’为 Value 建立映射表。在搜索时，ES 可以直接通过词典定位到包含该词的文档，不仅查询速度达到 O(1) 级别，还能根据词频等因素进行**相关性打分排序**，这是 MySQL 做不到的。”


这里可以再深入了解hash机制，虽然之前已经学了不少了，但是也忘了不少


因为 ES 和 MySQL 的**底层架构完全不同**。我们用**“寄快递”**的逻辑给你对照一下：


| MySQL 概念            | ES 对应概念                | 大白话解释                                                                                      |
| --------------------- | -------------------------- | ----------------------------------------------------------------------------------------------- |
| **数据库 (Database)** | **索引 (Index)**           | 相当于一个大仓库。ES 里没有数据库的概念，一个 Index 就是一个独立的数据集（比如`question_v1`）。 |
| **表 (Table)**        | **无**（直接就是 Index） | ES 没有表的概念。一个 Index 里直接放一堆数据。                                                  |
| **行 (Row)**          | **文档 (Document)**        | 一条具体的数据。在 ES 里就是一个 JSON 对象（比如一道具体的题目）。                              |
| **列 (Column)**       | **字段 (Field)**           | JSON 里面的 Key（比如`title`、`content`）。                                                     |
| **表结构 (DDL)**      | **映射 (Mapping)**         | 定义字段类型。比如规定`title`是文本，`tags`是关键字。                                           |
| **SQL 语句**          | **DSL 语句**               | ES 不用 SQL，改用 JSON 格式的查询语句（叫 DSL）。                                               |


关键点：

**“ES 里没有表，只有索引；没有行，只有 JSON 文档；没有 SQL，只有 DSL。”**
