# 手写ES搜索

## 自测题

### 面试官提问 1：为什么 `current` 要减 1？

a：因为分页的基准不同。前端展示的分页通常是从 **第 1 页** 开始（`current = 1`），而 Elasticsearch 底层的数组索引是从 **0** 开始的。
如果不减 1，后端把 `1` 传给 ES，ES 会把它当成第 2 页，导致前端查第一页时，会直接跳过前 `pageSize` 条数据，数据就会“丢失”或“错位”。

+：本质协议转换问题


### 面试官提问 2：关键词查询用 `should` 还是 `must`？为什么？

a：用 **`should`**。
因为对于搜索业务来说，用户输入的关键词往往并不一定能严格匹配到某一个字段。比如用户搜“JVM”，只要标题、内容、答案中**任意一个**包含即可。
使用 `should` 配合 `minimumShouldMatch(1)`，等价于 SQL 里的 `OR`，并且 `should` 会参与**相关度打分（`_score`）**，从而把最匹配的结果排在前面。如果用 `must`，就变成了 `AND`，必须三个字段全包含才能搜出来，这不符合搜索的实际预期。


### 面试官提问 3：ES 返回的 DTO 怎么变成前端要的 VO？

a:复用之前的封装逻辑。
ES 搜出来的是 `QuestionEsDTO`，我通过写好的 `dtoToObj` 方法将其转回 `Question` 数据库实体类，塞进 `Page<Question>` 里返回。
然后，Controller 层再调用 `getQuestionVOPage` 将实体转为 `QuestionVO`。这样无论底层是查 MySQL 还是查 ES，前端拿到的格式完全一致，做到了换数据源不换契约。


### 面试官提问 4：`BeanUtils.copyProperties` 在 tags 上会发生什么？

a:会**静默失败（跳过）**。
在 `Question` 实体中，`tags` 是 JSON 字符串（如 `"[\"Java\"]"`）；而在 `QuestionEsDTO` 中，`tags` 是 `List<String>` 集合。因为类型不匹配，`BeanUtils` 不会报错，而是直接不拷贝该字段。
如果不手动处理，存进 ES 的数据里，标签就会全部丢失，导致后续无法按标签过滤。


### 面试官提问 5：为什么生产环境要给搜索加数据库降级？

a:为了保证系统的**高可用性（HA）**。
ES 作为一个独立的中间件，可能会出现网络波动、节点宕机或 OOM 内存溢出等故障。如果搜索接口强依赖 ES，一旦 ES 挂掉，用户就完全无法搜索了。
加数据库降级（即用 `try-catch` 包裹 ES 请求，失败后回退到 MySQL 的 `LIKE` 查询），虽然速度慢、精确度低，但能保证核心业务不断供。这是大厂架构中容灾设计的底线。
