# 环境升级

## 自测题

### 面试官提问 1：为什么索引名叫 `question_v1`，而代码里写的是 `question`？

a：这是es中的“别名”机制（Alias）

question 是别名 question_v1 是真正的物理索引

在改动代码时候，只需要加一个新的索引，让question指向新的索引就可以了

+：所有大型分布式系统解决数据迁移和版本升级的通用思路


### 面试官提问 2：为什么 Redis 用 `database: 1` 而不是 0？

a：如果在一台电脑或服务器上面开发，redis默认用0端口，而我用1就相当于开了一个独特的房子，避免数据库里的东西互相打扰，a的缓存被b读走了


+：虽然 Redis 支持多个 database，但它的集群模式（Cluster）是不支持多 database 的。所以在真正的微服务架构中，我们通常会直接用不同的 Redis 实例（或者通过 Key 的前缀如 `mianshiya:user:`）来做隔离，而不是依赖 database 编号。


### 面试官提问 3：`ik_max_word` 和 `ik_smart` 有什么区别？

a：这两个是 IK 中文分词器提供的两种分词模式：

* `ik_max_word`（最细粒度）**：会把句子拆得极其碎。比如“什么是JVM”，它会拆成“什么是”、“什么”、“是”、“JVM”。它适合用在**建立索引时（写入数据时）**，因为拆得越细，被搜到的概率越大。
* **`ik_smart`（智能粒度）**：会做最粗粒度的拆分。比如“什么是JVM”，它只会拆成“什么是”、“JVM”。它适合用在**用户搜索时**，因为用户输入的关键词，没必要拆得太碎，能匹配上就行。

**💡 面试官想听的加分项**：
“在配置 ES 的 mapping 时，通常建索引（`index`）用 `ik_max_word`，搜索（`search_analyzer`）用 `ik_smart`，这样能最大化地平衡搜索的精准度和召回率。”


### 面试官提问 4：ES 装不上 IK 时，你的降级方案是什么？

a:如果是网络问题导致下载超时，我准备了两套方案：

1. **离线安装**：用浏览器手动下载对应版本（比如 7.17.9）的 IK 压缩包，通过 `docker cp` 命令复制进 ES 容器，然后再执行本地路径安装。
2. **降级兜底**：如果实在装不上，我会先用 ES 自带的 `standard` 分词器把整套业务逻辑跑通。虽然中文会被拆成单个汉字，搜索效果差，但至少能保证代码能编译、能运行，不耽误主流程的开发。
